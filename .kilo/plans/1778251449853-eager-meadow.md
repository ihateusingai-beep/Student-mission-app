# Technical Audit — Phase A Implementation

## Executive Summary

The Phase A implementation (Progress Tracking & Reflection) compiles cleanly and delivers core functionality. However, several functional bugs, edge-case vulnerabilities, and architectural issues were identified that should be addressed.

---

## Critical Issues

### 1. Date Parsing Year Boundary Bug — `WeeklyReview.ts:22-26`

```typescript
const weekLogs = logs.filter(log => {
  const [month, day] = log.time.split(' ')[0].split('/').map(Number);
  const logDate = new Date(now.getFullYear(), month - 1, day);
  return logDate >= weekAgo;
});
```

**Problem:** Assumes all logs are in the current year. Logs from December of a previous year would incorrectly pass the `weekAgo` filter when `now` is January. The `ActivityLog.time` format `"5/8 23:15"` contains no year component.

**Fix:** Parse year from `createdAt` on User, or store year explicitly in ActivityLog, or add year inference logic that handles January-December crossover.

---

### 2. Streak / DailyCompletion Date Format Mismatch — `WeeklyReview.ts:43` vs `WeeklyReview.ts:50`

```typescript
// dailyCompletion uses "MM/DD" format (from log.time)
const dateStr = log.time.split(' ')[0];  // "5/8"

// streak calculation uses "YYYY-MM-DD" format (from habitCalendar)
const dateStr = currentDate.toISOString().split('T')[0];  // "2026-05-08"
```

**Problem:** These two date format standards are incompatible. `dailyCompletion` keys like `"5/8"` will never match `habitCalendar` keys like `"2026-05-08"`. The streak calculation may be correct (uses ISO from habitCalendar), but `dailyCompletion` lookups are broken.

**Fix:** Use ISO `YYYY-MM-DD` consistently for all date keys.

---

### 3. Total Tasks Calculation Error — `WeeklyReview.ts:149-151`

```typescript
const totalTasks = summary.totalTasksCompleted + Object.keys(summary.dailyCompletion).reduce((sum, day) => {
  return sum + (summary.dailyCompletion[day] || 0);
}, 0);
```

**Problem:** `totalTasksCompleted` counts tasks from logs; `dailyCompletion` also counts tasks from logs. Adding them together double-counts. If `dailyCompletion` is meant to represent remaining/incomplete tasks, the data doesn't support that.

**Fix:** `totalTasks` should be `summary.totalTasksCompleted + incompleteTasksForTheWeek`. Either track incomplete tasks separately or use a counter derived from the task list.

---

### 4. Unused `t` (i18n) Variable — `SelfAssessment.tsx:40`

```typescript
const { t } = useI18n();  // Declared but never used
```

**Problem:** `t` is declared but all UI strings are hardcoded Chinese. If i18n is intended, this should be wired up. If not, remove the unused import.

## Algorithmic Efficiency Issues

### 5. Redundant Log Filtering — `WeeklyReview.ts:28-30`

```typescript
const totalTasksCompleted = weekLogs.filter(l => l.action === '完成任務').length;
const totalPointsEarned = weekLogs.filter(l => l.points > 0).reduce((sum, l) => sum + l.points, 0);
const totalPointsSpent = Math.abs(weekLogs.filter(l => l.points < 0).reduce((sum, l) => sum + l.points, 0));
```

**Problem:** `weekLogs` is iterated 3 times. Could be a single pass with an accumulator.

**Fix:**
```typescript
const stats = weekLogs.reduce((acc, log) => {
  if (log.action === '完成任務') acc.tasks++;
  if (log.points > 0) acc.earned += log.points;
  if (log.points < 0) acc.spent += Math.abs(log.points);
  return acc;
}, { tasks: 0, earned: 0, spent: 0 });
```

### 6. Duplicate `calculateAbilityLevel` — DRY Violation

`calculateAbilityLevel` in `WeeklyReview.ts:136` and `calculateLevel` in `AbilityProgress.tsx:36` are identical:

```typescript
function calculateLevel(value: number): number {
  return Math.floor(value / 100) + 1;
}
```

**Fix:** Export from `WeeklyReview.ts` and import in `AbilityProgress.tsx`.

## Edge Case Issues

### 7. Week Number Calculation May Be Incorrect — `WeeklyReview.ts:146-147`

```typescript
const startOfYear = new Date(now.getFullYear(), 0, 1);
const weekNumber = Math.ceil(((now.getTime() - startOfYear.getTime()) / 86400000 + startOfYear.getDay() + 1) / 7);
```

**Problem:** This formula does not produce ISO week numbers. ISO weeks start on Monday and week 1 is the week containing the first Thursday. The formula above can be off by one week near year boundaries.

**Fix:** Use `toISOString()` and parse `W` prefix, or use a library like `date-fns`.

---

### 8. Ability Name Parsing Fragile — `AbilityProgress.tsx:71`

```typescript
{data?.name?.replace(/^[^\s]+\s/, '') || key}
```

**Problem:** Assumes emoji is always followed by a space. If ability name format varies, this breaks.

**Fix:** Use a more robust approach, or store the display name separately from the icon.

---

### 9. Magic Number 100 — `AbilityProgress.tsx:37`, `WeeklyReview.ts:137`

The level calculation uses hardcoded `100`. This should be derived from `Ability.max` or a named constant.

---

## Architectural Issues

### 10. `WeeklyReview` Type vs `HeroReviewData` Interface

The `types/index.ts` defines `WeeklyReview` interface (lines 186-197) and `services/WeeklyReview.ts` defines `HeroReviewData` interface. They overlap significantly. Consolidate into one canonical interface.

### 11. `lang` Parameter Ignored in `formatWeeklySummaryText`

`formatWeeklySummaryText(summary, lang)` accepts `lang` but always outputs Chinese. Either implement i18n or remove the parameter.

### 12. `RUBRIC_DESCRIPTIONS` Should Be Extracted

The rubric descriptions are hardcoded Chinese in `SelfAssessment.tsx`. If i18n is implemented, these should come from `translations.ts`.
